# Hardcoded values review (main: d22fe6f, 2026-11-23)

Scope: current `main` product backend and frontend, with template screens considered separately. This review classifies *business meaning*, not every numeric literal or HTML label. It records decisions already present in the approved core rules and identifies implementation proposals that still require product approval. No runtime behavior is changed here.

## Classification rule

Keep a value in code when it defines an approved invariant, protocol, security floor, or implemented operation. Put deploy-specific secrets and endpoints in deployment configuration; put governed business choices in validated, authorized persistent settings with an explicit owner and scope. Defaults can remain in code as fallbacks, but must not masquerade as a saved setting. A UI label can be in code while its underlying legal/business value is stored separately. Never make an authorization check configurable merely by moving its string into a database.

## Findings to resolve before implementation

1. **Broken agent contract freshness check.** `scripts/check-agent-contracts.sh` exits `invalid or unavailable Verified source tree` on a full clone of `main`. The referenced `5a7cb264a34549135dbd2dd07df3bfccb2424451` is not a reachable object. The documented `git write-tree` procedure can record an uncommitted tree that is never pushed; the checker therefore fails for new agents. Change the reference to a committed reachable tree/commit and adjust the procedure/checker together after comparing watched source changes. The current reference cites `frontend/src/proxy.ts` and `frontend/src/components/auth/AuthenticatedLayout.tsx`, which are absent on this main checkout; reconcile citations rather than simply replacing the hash.
2. **Security setting coverage is fragmented.** Setup OTP and password-history policies have Main Portal setters, while proof expiry, lockout, temporary-password expiry, and several throttles are literals. Design one explicit ownership/precedence and enforce safe ranges before adding controls.
3. **Global settings are read-only despite the name.** Clearly label stable core and default proposals separately in UI. Financial-year inheritance and operator-editability require a product decision before implementation.
4. **Audit template reachability.** Decide which demo routes intentionally remain accessible; OTP-only policy forbids presenting activation-link guidance as a real CBMS flow. Replace live sign-in branding independently of this decision.

## Change order

First repair the contract checker on a reachable source tree; then make a focused, tested branding correction and trace exposed template routes. Implement the approved/configured boundaries (permission catalogue drift, settings ownership and financial-year rule) one at a time with backend validation, authorization and cross-stack tests. Keep this review as a dated snapshot; source code and approved decisions take precedence after later feature changes.
